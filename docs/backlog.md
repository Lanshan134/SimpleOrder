# 后续开发需求清单

记录日期：2026-10-19。以下均为待开发需求，尚未实现。后续逐项在 `beta` 开发，版本稳定后再合并 `main`。本次不发布新版本。

## [智能快速录入：名称与日期/时间解析及字段预览](https://github.com/Lanshan134/SimpleOrder/issues/1)

## 需求

在输入框输入“名称 + 日期/时间”，按回车自动识别并截取日期/时间，形成任务字段。支持一定程度的自然语言日期，例如“明天”。

- 管理窗口：识别结果直接填入对应表单字段。
- 悬浮窗：用不同颜色或淡化样式区分已识别字段，让用户知道哪些内容被识别为日期/时间。
- 兼顾原有纯名称快速添加流程。

## 示例（用于后续讨论）

`交报告 明天 18:00` → 名称“交报告”、日期为明天、时间 18:00。

## 已确认并实现的首版交互

- 支持后天、下周一、明确日期与无年份日期；无年份取下次有效日期。
- 名称框回车只填表；快速添加框实时预览，回车创建。
- 片段蓝色高亮，多个时间或日期不自动创建；手工字段冲突时保留原文。

## 验收方向

纯名称仍可录入；识别结果可确认或修正；未识别内容不丢失；管理器与悬浮窗的字段含义一致。

状态：Issue #1 已认领，本分支实现并提交面向 beta 的 PR；详见 [使用说明](smart-entry.md)。

## [悬浮窗 UI 调整：图标上栏、外观对比与窗口右键预留](https://github.com/Lanshan134/SimpleOrder/issues/2)

## 需求

悬浮窗上栏从文字按钮改为图标按钮，并重新梳理常用功能入口。比较圆角与直角外观，再确定视觉方案。

- 图标应能辨认功能；必要说明放悬停提示，避免长期占据界面。
- 整个悬浮窗的右键菜单暂未定义，可后续考虑退出程序等常用功能。
- 保留事项自身已有的右键操作，不与窗口级菜单混淆。

## 待确认

上栏最终保留哪些功能、图标样式、圆角/直角选择，以及窗口级右键菜单内容。暂不把“退出”等候选项当成已确定实现要求。

## 验收方向

图标入口清晰，窗口仍易于拖动；对比稿经确认后再实施最终样式。

状态：需求记录，尚未实现。后续在 beta 开发。

## [日历纵向展开：悬浮窗与管理窗口显示每日事项详情](https://github.com/Lanshan134/SimpleOrder/issues/3)

## 需求

悬浮窗和管理窗口都提供日历放大功能。优先向下展开，横向宽度保持不变，让每天能够显示更详细的任务信息。

- 管理窗口放大日历时，可压缩原任务详情编辑区域，为日历让出纵向空间。
- 支持恢复原先的紧凑日历布局。

## 待确认

展开高度、每格内容密度、事项过多时的滚动或更多入口，以及管理器详情区压缩后的形式。

## 验收方向

两个入口均可展开/收起；宽度保持不变；每天的任务更易查看；展开和恢复不丢失编辑草稿。

状态：需求记录，尚未实现。后续在 beta 开发。

## 验收方向

逐页清理常驻说明，检查界面密度与可理解性；不因清理文案而增加新的说明占位。

状态：需求记录，尚未实现。后续在 beta 开发。

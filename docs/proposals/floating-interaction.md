# 悬浮窗点击行为：现状、拟定规则与缺陷（Issue #18）

状态：缺陷 D1–D13 已修复，自检 `tests/interaction_smoke.cpp` 覆盖 D1–D10、D12、D13（D11 在隐藏窗口里无法验证）。表中“现在的实际结果”记录的是修复前的 v2.0.0。

**测量方法**：v2.0.0（c3dba16）真实控件，事件经 Qt 平台事件入口投递（由 Qt 自己决定接收者与双击），运行在 offscreen 平台，用其虚拟指针，不动真实鼠标；每个手势前后比对数据库、编辑器、窗口与调用次数，约 150 例。启动拖动阈值 10px，双击间隔 400ms。右键/中键拖动是直接投递到控件的；Windows 上“松开右键才弹菜单”，offscreen 是按下即弹。未在真实桌面上用鼠标复测。

标记：✅ 符合预期　⚠️ 歧义，需要选择　❌ 缺陷（编号见下节）

## 验收四场景

| 场景 | 结论 |
|---|---|
| 完成事项 | 单击通过；双击不通过（D1），按压滑动与指针滞后不通过（D2、D3） |
| 编辑事项 | 只触发一次；但左右键去处不同，计划会带动月历（D5） |
| 选日 | 平常通过；独立编辑窗开着或管理窗隐藏时会动到编辑器（D7、D8） |
| 拖动悬浮窗 | 通过；快速再次按住时不动（D9），无移动阈值 |

## 缺陷（客观误触，可不等规则确认先修）

全部已修复。顺带修复三处：没有选中事项时，管理器列表的键盘位置会落到分组标题上（`updateLists` 把标题行 id 0 当成了选中项）；快速添加框启动时不显示占位文字；缩放手柄压住添加按钮一角。D11 改为在发起手势的悬浮窗上询问，且对话框不继承悬浮窗的淡化颜色。D13 在预览中只提供“放弃”和“取消”。

| 编号 | 位置 | 修法 |
|---|---|---|
| D1 高 | `tasklist.cpp:132`，未处理双击；完成后重排 | `TaskList` 处理双击：吞掉第二次按下与随后的松开 |
| D2 高 | 同上，只看松开时的位置 | 按下时记下所在行与区，松开须一致 |
| D3 高 | `tasklist.cpp:138` `QCursor::pos()` | 用鼠标事件坐标 |
| D4 中 | `tasklist.cpp:238` 未限定按键 | 仅左键按下时允许 |
| D5 中 | `editor.cpp:173` 打开编辑就改 `day` | 去掉，或只对任务且由管理窗口发起时 |
| D6 中 | `tasklist.cpp:152` `clear()`；`controller.cpp:221` 只恢复 `selected` | `updateLists` 前后按 id 保存、恢复当前行 |
| D7 高 | `controller.cpp:263`、`292`、`349`、`371` | 独立编辑窗开着时选日 / 拖放 / 快速添加不改 `selected` |
| D8 中 | `controller.cpp:263` `isVisibleTo(manager)` | 改为面板真正可见 |
| D9 低 | `window.cpp:12` 只认 `MouseButtonPress` | 同样处理 `MouseButtonDblClick` |
| D10 低 | `updateLists` 只在刷新时恢复高亮 | 取消后恢复 |
| D11 中 | `editor.cpp:155` | 传入触发窗口 |
| D12 中 | `tasklist.cpp:139` 预览时落入 `else` | 预览中圆圈直接返回 |
| D13 低 | `editor.cpp:99` 预览中返回 false | `leaveEditor` 在预览中不提供保存 |

没有发现：`itemClicked` 与 `itemActivated` 一次单击双触发（本机 `activateOnSingleClick=0`）；日期格重复触发；添加按钮双击重复添加；空格长按连续完成（因 D6 当前行丢失而停住，**修 D6 时须同时忽略自动重复**）。

## 需要确认的选择

1. 左键点正文改为打开独立编辑窗（建议：是）。
2. 草稿存在时，对其他事项的完成 / 置顶 / 改期不再询问（建议：是）。
3. 计划能否拖到日历（建议：按次数与累计类不可拖，间隔与指定日期类保留）。
4. 窗口级右键：本次不定义（建议：维持无动作）。
